# Backend BookSwap

Задание 1 лабораторной работы № 2: создать приложение FastAPI и разделить
код по назначению. Используем обычные синхронные функции и сессии SQLAlchemy.

## Структура

```text
backend/
├── app/
│   ├── __init__.py
│   ├── main.py          # создание FastAPI и подключение маршрутов
│   ├── config.py        # настройки приложения из .env
│   ├── database.py      # движок PostgreSQL, фабрика сессий и get_db
│   ├── models.py        # базовый класс и будущие модели таблиц SQLAlchemy
│   ├── schemas.py       # схемы запросов и ответов Pydantic
│   ├── crud.py          # будущие операции с данными
│   ├── services.py      # будущие правила бизнес-логики
│   └── routes/
│       ├── __init__.py
│       └── health.py    # маршрут проверки работы API
├── .env.example        # пример настроек
├── .gitignore
└── requirements.txt    # зависимости Python
```

Модели SQLAlchemy описывают таблицы БД, а схемы Pydantic — формат и проверку
данных API. В следующих заданиях маршруты будут вызывать бизнес-логику
из `services.py`, а она — операции с БД из `crud.py`.
`main.py` собирает приложение из этих частей.

## Запуск

Нужен Python 3.10 или новее с модулями `venv` и `pip`.
Команды выполняются из корня проекта:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m uvicorn app.main:app --reload
```

- Проверка работы: http://127.0.0.1:8000/api/health
- Документация Swagger UI: http://127.0.0.1:8000/docs

Запрос `GET /api/health` возвращает `{"status":"ok"}`.
Этот маршрут работает без запущенной БД и проверяет только доступность API.

## Настройки и БД

`APP_NAME` задаёт название API. `DATABASE_URL` задаёт адрес PostgreSQL
и использует драйвер psycopg 3. Значения в `.env.example` предназначены
для локальной разработки: замените пользователя, пароль и название БД
на свои в `.env`. Файл `.env` исключён из Git.
Переменные окружения имеют приоритет над `.env`.

В `database.py` подготовлены движок, фабрика сессий и зависимость `get_db`.
Когда появятся маршруты для работы с данными, они будут получать сессию
через `Depends(get_db)`. Для каждого запроса создаётся отдельная сессия,
которая автоматически закрывается после обработки. Сохранение изменений
через `commit()` будет выполняться явно в операциях с данными.

На этом шаге PostgreSQL ещё не развёрнут, таблицы не создаются, CRUD
и правила бронирования не реализованы. Для них подготовлены отдельные модули.
Frontend пока использует демонстрационные данные.

Разделение маршрутов основано на [документации FastAPI](https://fastapi.tiangolo.com/tutorial/bigger-applications/).
